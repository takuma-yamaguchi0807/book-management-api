## POST /authors - 著者登録

### 処理概要

1. リクエストボディのバリデーション
2. 生年月日が現在より過去かチェック
3. 著者情報をデータベースに登録
4. 作成された著者 ID を返却

### 設計意図

#### レスポンス: 201 Created + id のみ

- **検討した選択肢**:
  1. `{ "id": 123 }` のみ
  2. 作成後のリソース全体を返す
- **選択**: 案 1
- **理由**: REST のベストプラクティスに沿う。レスポンスが軽量。必要なら別途 GET で取得可能
- **トレードオフ**: 作成後の情報を取得するには追加リクエストが必要

#### エラーレスポンス: 生年月日が未来の場合

- **検討した選択肢**:
  1. 400 Bad Request
  2. 422 Unprocessable Entity
- **選択**: 案 1
- **理由**: バリデーションエラーとして扱う
- **トレードオフ**: 422 を使うとセマンティックエラーとして区別できるが、バリデーションエラーとして統一する方がシンプル

## PUT /authors/{id} - 著者更新

### 処理概要

1. 指定された著者 ID が存在するかチェック
2. リクエストボディのバリデーション
3. 生年月日が現在より過去かチェック
4. 著者情報を更新
5. 204 No Content を返却

### 設計意図

#### HTTP メソッド: PUT vs PATCH

- **検討した選択肢**:
  1. PUT（全フィールド必須）
  2. PATCH（部分更新）
  3. 両方提供
- **選択**: 案 1
- **理由**: 実装がシンプルで明確。全フィールド送信により整合性を保ちやすい
- **トレードオフ**: 一部更新でも全フィールド送信が必要だが、今回の要件では全フィールド更新で十分

#### レスポンス: 204 No Content

- **検討した選択肢**:
  1. 204 No Content（レスポンスボディなし）
  2. 200 OK + 更新後のリソース全体
- **選択**: 案 1
- **理由**: ID も変更後の値も知っているため、何も返す必要がない
- **トレードオフ**: 更新後の内容を確認するには別途 GET が必要

#### エラーレスポンス: 著者 ID が存在しない場合

- **検討した選択肢**:
  1. 404 Not Found
  2. 400 Bad Request
- **選択**: 案 1
- **理由**: 直接リソースを取得/更新する場合に 404 を使用するのが REST のベストプラクティス
- **トレードオフ**: なし（直接リソース操作の場合は 404 が適切）

## POST /books - 書籍登録

### 処理概要

1. リクエストボディのバリデーション
2. 価格が 0 以上かチェック
3. 著者 ID が 1 名以上かチェック
4. 指定された著者 ID が存在するかチェック
5. 書籍情報をデータベースに登録
6. 作成された書籍 ID を返却

### 設計意図

#### レスポンス: 201 Created + id のみ

- **選択**: POST /authors と同様

#### エラーレスポンス: 著者 ID が存在しない場合

- **検討した選択肢**:
  1. 400 Bad Request
  2. 404 Not Found
  3. 422 Unprocessable Entity
- **選択**: 案 3
- **理由**:
  - リクエストの形式は正しいが、セマンティックエラー（参照先リソースが存在しない）
  - WebDAV の拡張だが、REST API で広く使用されている
  - バリデーションエラー（400）とは区別したい
- **トレードオフ**:
  - 400 を使うとバリデーションエラーと区別がつかない
  - 404 は意味合い的にはエンドポイントのリソースに対してなので、異なると判断。

## PUT /books/{id} - 書籍更新

### 処理概要

1. 指定された書籍 ID が存在するかチェック
2. リクエストボディのバリデーション
3. 価格が 0 以上かチェック
4. 著者 ID が 1 名以上かチェック
5. 指定された著者 ID が存在するかチェック
6. 出版済み → 未出版への変更不可チェック
7. 書籍情報を更新
8. 204 No Content を返却

### 設計意図

#### HTTP メソッド: PUT vs PATCH

- **選択**: PUT /authors/{id} と同様

#### レスポンス: 204 No Content

- **選択**: PUT /authors/{id} と同様

#### エラーレスポンス: 出版済み → 未出版への変更不可

- **検討した選択肢**:
  1. 400 Bad Request
  2. 422 Unprocessable Entity
- **選択**: 案 1
- **理由**: ビジネスルール違反として 400 で返す。`BUSINESS_RULE_VIOLATION` コードで区別
- **トレードオフ**: 422 を使うとセマンティックエラーとして区別できるが、ビジネスルール違反は 400 で統一

#### エラーレスポンス: 著者 ID が存在しない場合

- **選択**: POST /books と同様（422）

## GET /authors/{id}/books - 著者に紐づく書籍一覧取得

### 処理概要

1. 指定された著者 ID が存在するかチェック
2. ページネーションパラメータのバリデーション
3. 指定された著者 ID に紐づく書籍を取得（ページネーション適用）
4. 各書籍の著者情報を埋め込む
5. 書籍一覧とページネーション情報を返却

### 設計意図

#### エンドポイント設計: パスパラメータ vs クエリパラメータ

- **検討した選択肢**:
  1. `/authors/{id}/books`（パスパラメータ、単一著者 ID）
  2. `/books?authorIds=1,2,3`（クエリパラメータ、複数著者 ID 対応）
  3. body に持つ。
- **選択**: 案 1
- **理由**:
  - AND/OR 条件の指定が不明確になる
  - 複数著者での絞り込みは要件に含まれていない。
- **トレードオフ**: 複数著者での絞り込みはできないが、要件に含まれていないため問題なし

#### ページネーション: offset/limit vs cursor-based

- **検討した選択肢**:
  1. `offset` と `limit`
  2. cursor-based
- **選択**: 案 1
- **理由**:
  - より直感的で理解しやすい
  - ページ番号での移動が可能
  - 総件数と総ページ数で進捗を把握可能
  - 著者が数百万件もの本と執筆するとは考えられないと想定。
- **トレードオフ**:
  - offset/limit は実装が簡単だが、大量データでは offset が遅くなる可能性（今回の要件では問題にならない）
  - cursor-based は大量データに強いが、実装が複雑でページ番号での移動ができない

#### 著者情報の埋め込み: ID のみ vs 情報を埋め込む

- **検討した選択肢**:
  1. 著者 ID のみ（`authorIds: [1, 2]`）
  2. 著者情報を埋め込む（`authors: [{ id, name }]`）
  3. クエリパラメータで制御（`?include=authors`）
- **選択**: 案 2
- **理由**:
  - REST API のベストプラクティス（リソースの埋め込み）
  - N+1 問題を回避
  - 1 リクエストで必要な情報を取得可能
  - 一覧表示で著者名が必要なことが多い
- **トレードオフ**:
  - レスポンスサイズが増加するが、許容範囲
  - クエリパラメータで制御すると柔軟だが、実装が複雑（今回の要件では不要）

## 共通設計判断

### エラーレスポンス形式

#### 400 系、422 系: ValidationErrorResponse

- **検討した選択肢**:
  1. `key: message` 形式（1 つのフィールドに 1 つのメッセージ）
  2. `key: [message1, message2]` 形式（1 つのフィールドに複数のメッセージ）
- **選択**: 案 1
- **理由**: 機能要件を確認した結果、1 つのフィールドで複数のエラーメッセージが必要なケースは想定しにくい
- **トレードオフ**: 将来的に複数メッセージが必要になった場合、形式を変更する必要がある

#### 配列内の特定要素に対するエラー: `authorIds[1]` 形式

- **検討した選択肢**:
  1. `authorIds[1]` 形式（インデックス指定）
  2. `authorIds` のみ（配列全体として扱う）
- **選択**: 案 1
- **理由**: どの配列要素でエラーが発生したかを明確に示す
- **トレードオフ**: なし（配列インデックスを指定するのが一般的）

### エラーコード

- `VALIDATION_ERROR`: バリデーションエラー
- `INVALID_REQUEST`: リクエストボディが不正
- `RESOURCE_NOT_FOUND`: 参照先リソースが存在しない（422 エラー）
- `BUSINESS_RULE_VIOLATION`: ビジネスルール違反
- `AUTHOR_NOT_FOUND`: 著者が存在しない（404 エラー）
- `BOOK_NOT_FOUND`: 書籍が存在しない（404 エラー）
- `INTERNAL_SERVER_ERROR`: サーバー内部エラー
